Pulser — User Manual

Starting the LabRAD manager and Pulser server, writing pulse sequences, and configuring TTL channels.

Applies to the modern (2026) stack: scalabrad manager + pylabrad (py3) + the Pulser LabRAD server, which is a thin shim over the headless pulser3 driver for the Opal Kelly XEM7305.

Overview

The pulse sequencer is driven through a small stack of layers. You normally interact at the top (a LabRAD client); each layer just forwards work down to the FPGA.

  ┌─────────────────────────┐
  │  Your client / GUI      │   pylabrad (py3): connect, program, run
  └───────────┬─────────────┘
              │  LabRAD protocol (TCP 7682)
  ┌───────────▼─────────────┐
  │  scalabrad  (manager)   │   JVM broker + registry; routes requests
  └───────────┬─────────────┘
              │
  ┌───────────▼─────────────┐
  │  Pulser  LabRAD server  │   pulser_labrad/pulser_server.py  (thin)
  └───────────┬─────────────┘
              │  delegates every action to…
  ┌───────────▼─────────────┐
  │  pulser3.Driver / Sequence   compile → DDR3, start/stop, PMT counts
  └───────────┬─────────────┘
              │  Opal Kelly FrontPanel (USB 3)
  ┌───────────▼─────────────┐
  │  XEM7305 FPGA (photon.bit)   DDR3 program store, sequencer, PMT
  └─────────────────────────┘
Two ways to drive it

Through LabRAD (this manual's main path) — the manager + Pulser server run continuously; clients connect over the network. Use this for the experiment.

Headless — call pulser3 directly from a Python script, no manager needed. Good for bring-up and testing. See Headless.

One-time setup

Do these once per machine. (Already done on the current bench PC — kept here for a fresh install.)

1. Java (for scalabrad)

Install a JDK 8 or 11 — use Eclipse Temurin 11 (free OpenJDK, no Oracle account). Tick “Set JAVA_HOME” and “Add to PATH” in the installer. Verify with java -version.

Windows gotcha — spaces in the path

If Java lives in C:\Program Files\…, the labrad.bat launcher breaks on the space ('C:\Program' is not recognized). Fix by pointing JAVA_HOME at the short (8.3) form and persisting it. In PowerShell — this auto-finds a Temurin JDK:

$jdk = (Get-ChildItem 'C:\Program Files\Eclipse Adoptium' -Directory | Where-Object Name -like 'jdk*' | Select-Object -First 1).FullName
$short = (New-Object -ComObject Scripting.FileSystemObject).GetFolder($jdk).ShortPath
$env:JAVA_HOME = $short
[Environment]::SetEnvironmentVariable('JAVA_HOME', $short, 'User')   # persist for future windows
& "$env:JAVA_HOME\bin\java.exe" -version

Prints a short path like C:\PROGRA~1\ECLIPS~1\JDK-11~1.101 and the OpenJDK version banner.

Why it comes back: $env:JAVA_HOME = … alone lasts only for that one window — open a fresh PowerShell and the 'C:\Program' error returns. The [Environment]::SetEnvironmentVariable(…, 'User') line writes it to your account permanently, so it survives new windows. (Alternatively reinstall the JDK to a no-space folder like C:\Temurin\jdk-11.)

2. scalabrad manager

Download a release from github.com/labrad/scalabrad/releases and extract it. The launchers are in scalabrad-<ver>\bin\ (labrad.bat on Windows; the extension-less labrad is for Mac/Linux).

3. Python packages (py3)

python -m pip install pylabrad twisted numpy pyopenssl
python -m pip install "numpy<2"    # pylabrad uses np.bool8, removed in numpy 2.0
Important

Pin numpy<2 — pylabrad 0.98.x imports np.bool8, which numpy 2.0 removed, so import labrad fails otherwise. (Safe: pulser3 itself is numpy-free.)

Starting the system

Three windows: the manager, the Pulser server, then your client. Start them in that order.

Step 1 — Start the LabRAD manager

Create its two working directories once (scalabrad won't create them itself):

mkdir C:\labrad-registry
mkdir C:\Users\thanedp\.labrad

Then, from scalabrad-<ver>\bin\ (with JAVA_HOME set — see setup):

.\labrad.bat --registry "file:///C:/labrad-registry?format=binary" --password test --tls-required false

It should log now accepting labrad connections: port=7682 and stay running. Leave this window open. (Any netty "illegal reflective access" WARNINGs on JDK 11 are harmless — ignore them.)

Point --registry at an EMPTY directory

Always use format=binary (not delphi), and give it a clean folder. If the manager crashes on startup with an IndexOutOfBoundsException … BinaryFileStore.decodeData … Registry.<init> stack trace, the registry folder holds a corrupt/half-written entry (typically a leftover from an earlier failed format=delphi run). The fix is to wipe the folder — never to switch formats:

Remove-Item -Recurse -Force C:\labrad-registry; mkdir C:\labrad-registry

then relaunch. Safe as long as you have no real settings stored yet (a fresh setup doesn't).

Not a web page

Port 7682 speaks LabRAD's binary protocol, not HTTP — don't open it in a browser (that spams the log with harmless Invalid login packet errors). You talk to it only through LabRAD clients.

Step 2 — Start the Pulser server

New window. Set the LabRAD environment (must match the manager's password + TLS) and the bitstream path, then run the server from Python_files:

$env:LABRADHOST = "localhost"
$env:LABRADPASSWORD = "test"
$env:LABRAD_TLS = "off"
$env:PULSER_BIT_PATH = "C:\...\build\xem7305_pulser.runs\impl_1\photon.bit"
cd C:\Users\thanedp\Desktop\pulse_sequencer\Python_files
python pulser_labrad\pulser_server.py

It configures the FPGA (Pulser: connecting… → FPGA ready.) and registers with the manager as Pulser. Leave it running.

Tip

PULSER_BIT_PATH must point at a valid photon.bit — the server reconfigures the FPGA on startup. Rebuild the bitstream in Vivado when the RTL changes; the server just loads whatever you point it at.

Step 3 — Verify

New window (same LabRAD env), run the bundled smoke test:

python pulser_labrad\test_client.py

Expected output ends with:

sequence done: True
PASS -- scalabrad -> Pulser server -> pulser3 -> FPGA works end to end
Easier: the Launcher

Steps 1–3 can all be done from one GUI instead of separate PowerShell windows. The LabRAD Launcher (labrad_launcher/labrad_launcher.py) starts the manager, discovers the servers in a folder, and starts/stops each with a button — capturing every log in its own tab. It also connects to the manager and shows, per server, whether it's actually registered (not just running), plus a live list of all connected servers (the built-in Manager / Registry / Auth and everything you started). See The Launcher.

The Launcher (one-window control center)

Instead of a PowerShell window per server, labrad_launcher/labrad_launcher.py brings the whole stack up from one GUI. It spawns and supervises every process itself (no LabRAD-node config), and it also connects to the manager so it doubles as the live "what's connected" view.

pip install PyQt5
python labrad_launcher\labrad_launcher.py
  1. Manager — set the path to your scalabrad labrad.bat, then Start Manager. Its log appears in the Manager tab. (JAVA_HOME must be set, as for running it by hand.)
  2. Servers — Browse to a folder (e.g. Python_files) and it lists every server it finds (files with a ### NODE INFO block), skipping the legacy py2 trees. Start a row or Start All; each server's output gets its own tab.
  3. Environment — the key/value table is applied to every server it launches (pre-seeded with the LABRAD* vars and PULSER_BIT_PATH). Save config to remember it all.

Each server row shows two states: Process (is the OS process alive?) and Manager (is it actually registered with the manager?) — the gap between them catches "running but failed to connect". The Connected to manager panel lists every registered server, built-ins included, and it reconnects on its own if the manager restarts. Config is saved to ~/.labrad/launcher_config.json.

Data Vault first run

Data Vault prompts once (on stdin) for its storage directory. Start it from a terminal the first time to answer the prompt; afterwards the path is saved in the registry and it starts silently under the launcher.

Writing a pulse sequence

A sequence is built from TTL pulses in real units (seconds), then compiled and run. From a Python client:

import labrad
from labrad.units import s

cxn = labrad.connect()                 # uses LABRAD* env vars
p = cxn.pulser                         # the Pulser server

p.new_sequence()                       # start a fresh sequence
p.add_ttl_pulse('sMOT_PROBE', 0.1*s, 0.5*s)   # channel, start, duration
p.add_ttl_pulse('BIG_MOT_SH', 0.3*s, 0.5*s)
p.extend_sequence_length(1.0*s)        # optional: pad total length

p.program_sequence()                   # compile -> load into DDR3
p.start_single()                       # run it once
done = p.wait_sequence_done(5.0)       # True if finished within 5 s
print('done:', done)
How the timing works
  • Times are in seconds; the hardware tick is 40 ns, so times round to the nearest 40 ns.
  • A pulse turns a channel ON at start and OFF at start+duration. Overlapping pulses on different channels are fine; two pulses overlapping on the same channel are rejected.
  • The maximum single-pass length is ~85 s (31-bit time field). Loops repeat that.
  • Channels not mentioned stay OFF. The sequence ends automatically (an all-off terminator is appended by the compiler).

Running modes

CallEffect
p.start_single()Run the program once.
p.start_infinite()Loop forever until p.stop_sequence().
p.start_number(N)Loop exactly N times.
p.stop_sequence()Stop any running sequence.
p.wait_sequence_done(t)Block up to t s; returns True if it finished.
p.repeatitions_completed()Loops completed so far (infinite/number modes).
You don't need to stop before re-programming

program_sequence() stops any prior run and cleans up the DDR3 state automatically, so you can program → run → program → run indefinitely from a long-lived client.

Configuring TTL channels

Channel names map to hardware TTL line numbers in one place:

Python_files/pulser3/hwconfig.py → the CHANNELS dictionary.

CHANNELS = {
    'ttl_0':            0,   # camera
    'sMOT_PROBE':       1,
    'sMOT_PROBE_SPIN':  2,
    'BIG_MOT_SH':       3,
    'sMOT_AO':          4,
    'BIG_MOT_AO':       5,
    '405_ECDL':         6,
    # … up to channel 31 …
}

To add or rename a channel

  1. Edit CHANNELS: add a line 'my_channel': 12, (name → the physical TTL line number, 0–31).
  2. Save. Restart the Pulser server (it loads the map at startup).
  3. The name is now usable everywhere: p.add_ttl_pulse('my_channel', …), and it shows up in p.get_channels().
Notes
  • Valid channel numbers are 0–31 (32 TTL lines). Numbers 0–5 also drive the on-board LEDs, handy for eyeballing.
  • Two names may share a number (e.g. AO2 and B_x_sign are both 21) — two labels for one physical line. That's allowed.
  • Channel 16 (DiffCountTrigger) and channel 0 (866) have special meaning for differential PMT counting — avoid repurposing them if you use that mode.

Switch Control GUI

A PyQt5 GUI for driving the TTL channels by hand lives in Python_files/pulser_gui/ (a Python-3 / PyQt5 port of the legacy PyQt4 client). Each switchable channel gets three buttons:

ButtonEffect
ON / OFFForce that TTL output high/low via the manual override, independent of any running sequence.
AutoReturn the channel to sequence control.

Buttons reflect the live state; a twice-a-second poll of Get State keeps them in sync when another client (or a running sequence's Auto channels) changes something. Only channels wired for override (number 0–11) appear.

Run it

pip install PyQt5
# manager + Pulser server already running (see above), same LabRAD env
cd Python_files/pulser_gui
python switch_control.py
No qt5reactor

The GUI uses pylabrad's blocking client and a plain Qt event loop — not Twisted/qt5reactor, which conflicts with modern PyQt5 on Windows (it floods QCoreApplication::exec: The event loop is already running and the window comes up empty). It reads the same LABRADHOST / LABRADPASSWORD / LABRAD_TLS environment as the server and test clients.

Headless use (no LabRAD)

For bring-up and testing you can skip the manager/server entirely and drive the FPGA directly with pulser3. Run from Python_files (needs the Opal Kelly ok module on the path, same as the FPGA test scripts).

from pulser3 import Driver
from pulser3 import hwconfig

d = Driver()
d.connect(r"C:\...\photon.bit")          # ConfigureFPGA + MIG calibration

seq = hwconfig.new_sequence()             # named channels, 40 ns ticks
seq.add_pulse('sMOT_PROBE', 0.1, 0.5)      # seconds (plain floats here)
seq.add_pulse('BIG_MOT_SH', 0.3, 0.5)

d.load_program(seq.to_lines())            # compile -> DDR3
d.start_single()
print('done:', d.wait_done(5.0))

Three counting modes are implemented in the FPGA and exposed by pulser3.Driver. Until the detector is wired to a pin, an on-FPGA synthetic source at a known rate stands in, so the whole path is testable.

The Pulser is one server in a larger trapped-ion control stack that's being ported from the legacy Python-2 code to Python-3 on the same scalabrad manager. They all share the manager, the same LabRAD env, and the blocking-client / PyQt5 patterns used here. Ported so far:

Roadmap

The port so far covers the full PMT measurement loop (FPGA → Pulser → NormalPMTFlow → Data Vault → live plot) plus the operator GUIs. What's next, in dependency order:

Cross-platform

The whole stack is cross-platform Python (scalabrad/JVM + pylabrad + PyQt5/pyqtgraph). It has been run on Windows so far; on Mac/Linux everything should run natively — see Running on Mac / Linux. The hardware-free tools (sequence viewer/editor) run anywhere with just PyQt5 + pyqtgraph.

Turns "instruments you drive by hand" into "experiments you run and scan." Its dependencies (ParameterVault + Data Vault) are done.

  • script_scanner_gui (PyQt4→PyQt5) — the experiment-runner GUI (queue, progress, scan setup); would become a dashboard panel.
  • Experiment layer — experiment_scripts/ (MOT_loading, Clock_spectrum…), pulser_sequences/ (replace py2 treedict), analog_sequences/.

Running on Mac / Linux

The whole stack is cross-platform Python, so it runs natively on Mac and Linux — the differences from the Windows instructions above are small:

  • Manager — use the extension-less bin/labrad script instead of labrad.bat: 
    mkdir -p ~/labrad-registry ~/.labrad
./bin/labrad --registry "file://$HOME/labrad-registry?format=binary" --password test --tls-required false
    In the Launcher, point the Launcher field at that bin/labrad script; it runs and stops it natively (no cmd/taskkill).
  • No JAVA_HOME short-path dance — the C:\Program Files space problem is Windows-only. Just have a JDK 8/11 on the path.
  • Python deps are identical: pip install pylabrad twisted "numpy<2" pyopenssl PyQt5 pyqtgraph h5py.
  • Hardware access — the Pulser server needs the Opal Kelly FrontPanel SDK + USB driver for your OS (Opal Kelly ships Mac and Linux builds); the FPGA and bitstream are the same. Without FrontPanel, everything hardware-free still runs — notably the sequence viewer/editor, which import pulser3 without the ok module.
Status

Cross-platform by design (the only OS-specific code is in the Launcher, and it's guarded). Exercised on Windows so far; a first run on Mac/Linux is the remaining confirmation (see Roadmap Phase E).

Troubleshooting

SymptomCause & fix
'C:\Program' is not recognized when starting labrad.bat — especially if it worked before and came back Space in the Java path, and JAVA_HOME is unset in this window. A session-only $env:JAVA_HOME = … is lost when you open a fresh PowerShell. Set the 8.3 short path permanently with [Environment]::SetEnvironmentVariable('JAVA_HOME', $short, 'User'). See setup.
invalid format for registry file The registry directory doesn't exist yet. mkdir C:\labrad-registry first, then use ?format=binary.
Manager crashes at startup: IndexOutOfBoundsException … BinaryFileStore.decodeData … Registry.<init> A corrupt/half-written entry in the registry folder (often a leftover from a failed format=delphi run). Wipe it: Remove-Item -Recurse -Force C:\labrad-registry; mkdir C:\labrad-registry, then relaunch with ?format=binary. Don't switch formats.
'…\.labrad' does not exist (SQLite) Create the auth-store folder: mkdir C:\Users\<you>\.labrad, then restart the manager.
module 'numpy' has no attribute 'bool8' numpy ≥ 2.0 with pylabrad. pip install "numpy<2".
Client can't connect / TLS handshake error Set LABRAD_TLS=off in the client window and start the manager with --tls-required false. Password must match (LABRADPASSWORD = manager --password).
Manager log floods with Invalid login packet A browser (or other HTTP tool) is hitting port 7682. Harmless — close the tab. LabRAD isn't a web server.
DDR3 write-verify mismatch / write path never reported idle after several runs A persistent-session lifecycle issue — already handled: the server stops + resets before each re-program and skips the idle-sensitive verify read. If you see it, make sure the server is on the latest code (restart it after a git pull).
Server: FPGA not connected / can't find ok Run from an environment where the Opal Kelly FrontPanel ok module imports (the same one the FPGA test scripts use), and set PULSER_BIT_PATH.
GUI: No module named 'PyQt5' pip install PyQt5 in the same interpreter you launch the GUI with. See Switch Control GUI.
GUI window empty + console floods QCoreApplication::exec: The event loop is already running An old qt5reactor-based GUI on modern PyQt5. The current switch_control.py doesn't use qt5reactor — git pull and rerun. (If you wrote your own async client, drop qt5reactor and use the blocking labrad.connect() pattern.)
GUI window shows Cannot reach LabRAD / Pulser or Pulser not available instead of buttons The GUI's window doesn't have the LabRAD env set, or the manager/server isn't up. Set LABRADHOST/LABRADPASSWORD/LABRAD_TLS, confirm both are running, then relaunch.
Unknown channel … The name isn't in hwconfig.CHANNELS. Add it (see TTL channels) and restart the server. p.get_channels() lists valid names.
