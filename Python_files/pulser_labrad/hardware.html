DDS Slave Board — Hardware Design Summary

The DDS board the XEM7305 pulser drives over the Eurocard backplane to generate RF for AOMs. This captures the design decisions taken so far.

Companion to the software Pulser manual. Status: design/planning — not yet built. Point-in-time as of 2026-09-22 (RF signal-path BOM finalized); verify parts/specs against datasheets before committing a layout.

Overview

Each DDS card sits in a Eurocard rack. The XEM7305 pulser streams a per-board frequency/phase/amplitude table into the card and issues broadcast triggers; the card's FPGA plays that table out to an AD9912 DDS on each step_to_next, and the RF passes through an amplitude/gating chain to the AOM. An on-board Raspberry Pi Pico W is the local supervisor (config-loads the FPGA, does standalone/bench control, WiFi/USB).

Design philosophy

Two clean lanes: a fast, hardware-timed experiment path (pulser → FPGA → AD9912, phase-coherent, ns/µs timing) and a slow supervisor path (Pico W — config, CW setpoints, housekeeping, WiFi). The Pico is never in the timing-critical loop. The FPGA is a "config-memory + SPI streamer" — the old on-FPGA frequency sweep engine is dropped.

FPGA — Lattice ECP5

LFE5U-25F-6BG256C — 24k LUT4, 1,008 Kbit EBR, caBGA-256 (0.8 mm, 14×14 mm), 197 I/O. Chosen over Cyclone 10 for the open-source toolchain (Yosys + nextpnr-ecp5 + Trellis) and generous RAM. Heavily oversized once the sweep engine is dropped — the real gate is the AD9912 config table RAM.

  • Package is caBGA-256 — for fanout reference use Colorlight 5A-75B community KiCad (same package), not OrangeCrab (csfBGA-285).
  • Order the bare PCB with ENIG finish (BGA/QFN coplanarity).
  • ECP5 is SRAM-based → needs external config every power-up (the Pico W's job).

Configuration — Pico W loader

Decision: an on-board Raspberry Pi Pico W holds the bitstream in its 2 MB flash and config-loads the ECP5 via slave-SPI at power-up (PROGRAMN → wait INITN → stream bitstream → check DONE). It earns its place by doubling as the supervisor (standalone CW/bench control, WiFi/USB reflash, housekeeping) — that second job is what justifies it over a bare boot flash.

OptionWhen
A — master-SPI boot from a passive flash + JTAG headerleanest, if config is the only need (no on-board USB — reflash via external probe)

Flash budget (2 MB): LFE5U-25 bitstream ≈ 0.57 MB (uncompressed) + C/C++ WiFi app ≈ 0.5 MB (incl. the ~224 KB CYW43 blob) ≈ 1.1 MB → ~1 MB free (room for a golden-fallback bitstream). Use C/C++, not MicroPython (its ~1.5 MB interpreter would crowd out the bitstream).

pico-ice (RP2040+iCE40) for the config-controller firmware pattern; Lattice TN-02039 (ECP5 sysCONFIG) for the slave-SPI byte sequence; openFPGALoader / ecpdap as known-good implementations + JTAG bring-up.

Config table & RAM sizing

Each sequence step = one row of setpoints (store payload only; the ECP5 adds SPI/DAC framing at stream time):

Row total76 raw / 80 byte-aligned (10 B)use 80; +8-bit control byte → 88 if per-row flags wanted

Sizing on the LFE5U-25 (EBR = 1,008 Kbit): 8192 rows × 80 bit = 640 Kbit ≈ 62% of EBR raw (~65–85% after block-mapping) → fits comfortably. Use 213 depth; pad the row width to a multiple of 9/18 bits for efficient block packing. Step to LFE5U-45 only if you need >~12k rows.

Programming time

10 boards × 8192 rows × 80 bit = 6.4 Mbit total (sent per-board, sequentially). At 25–50 MHz serial clock that's ~0.13–0.26 s — a one-time setup cost. During scans, rewrite only changed lines (ms), not full tables.

DDS chip — AD9912

1 GSPS, 48-bit FTW (~3.6 µHz resolution), integrated 14-bit RF-output DAC, SPI-configured. Wins on frequency resolution and simplicity. What it gives up vs the AD9915: no digital amplitude control (→ external VGA), no hardware profiles, no on-chip RAM/digital ramp.

The load-bearing design rule

Double-buffer the frequency. During each dwell, the ECP5 pre-stages the next 48-bit FTW into the AD9912 over SPI (~1–2 µs). On step_to_next it just pulses IO_UPDATE → the switch is ~ns and deterministic. As long as dwell ≫ SPI write time, this fully hides the lack of hardware profiles.

Digital lines ECP5 ↔ AD9912: SCLK, SDIO, SDO, CSB, IO_UPDATE (4-wire SPI) + RESET (hard reset — easy to miss), optional PWRDWN. Keep the AD9912 running continuously for phase coherence; never power it down to gate RF.

Two output paths — use the sine, not the clock

The AD9912 has two separate outputs. Use PATH 1: DAC_OUT/DAC_OUTB (pins 50/51) = the 14-bit DAC analog sine — internal 50 Ω to AVSS, full-scale ~20 mA set by DAC_RSET (pin 48 = 10 kΩ), max fout ≈ 0.4×fS = 400 MHz. AC-couple it straight into the RF chain (DC return is internal — no external bias resistors). Do NOT use PATH 2: FDBK_IN → OUT/OUT_CMOS is the square-wave clock generator (loops the filtered sine back in, squares it, optional 2× doubler — for ADC/FPGA/LO clocks). A square wave's harmonics are wrong for an AOM. Leave FDBK_IN/OUT/OUT_CMOS unconnected and power down the HSTL + CMOS drivers.

SYSCLK — drive 1 GHz directly (PLL bypassed)

Best jitter = feed the clean external 1 GHz straight into SYSCLK/SYSCLKB (AC-coupled) with the SYSCLK PLL bypassed. Then: LOOP_FILTER (pin 31) = 1 kΩ to analog GND (not the R-C loop-filter network — that's only for the PLL multiplier); power down the SYSCLK PLL (Reg 0x0010 bit 4); CLKMODESEL (pin 32) left unconnected. Never clock the DDS from the ECP5 (OSCG ±7–15 % + jitter → bad accuracy/phase noise). For an optional on-board fallback, use a dedicated clean XO/MEMS → SYSCLK PLL, selectable at build time via DNP jumpers (dual LOOP_FILTER footprints) — not a runtime mux (that degrades the 1 GHz).

Why these choices

ETC1-1-13 is a transmission-line transformer (pin 1↔pin 5 DC-connected — not an isolation transformer), but that's irrelevant here because every amplifier pin is AC-coupled with 100 pF at the transformer: caps block DC, chokes set the ADL5330 output bias. No center tap needed. Choke rule: wirewound with SRF ≥ 2× fmax — the TDK MLF1608 (SRF = 400 MHz, multilayer ferrite) was rejected for that reason. Cap rule: must be C0G, never X5R/X7R (RF loss/distortion).

AC-coupling / RF-ground cap value vs AOM frequency

The 6 AC-coupling caps double as series coupling (in the 50 Ω line) and cold-side RF ground, so their reactance Xc = 1/(2πfC) must stay small vs 50 Ω. 100 pF is fine near 400 MHz but ~20 Ω at 80 MHz (too high). Since the board runs a few fixed AOM frequencies, swap all 6 caps together to the value below for the target band (aim Xc ≈ 2 Ω; SRF stays well above the band). All C0G/NP0, 0603, 50 V — same Samsung CL10C family as the 100 pF.

Part numbers follow Samsung's CL10C<value>JB8NNNC pattern; confirm each LCSC C-code and C0G/50 V availability before ordering.

Amplitude — VGA + DAC

VGA: original board uses ADL5330 (0–1.4 V gain control, ~60 dB, linear-in-dB). If out of stock: AD8367 (45 dB, ≤500 MHz) or AD8368 (34 dB, ≤800 MHz, has an ENBL shutdown) as drop-ins; or a digital step attenuator + fixed amp (quieter, drops the DAC).

DAC: replace the old fast parallel AD9744 with a cheap SPI voltage DAC — MCP4821 (single 12-bit) or MCP4822 (dual); 16-bit DAC80501/DAC8560 to hold 14-bit resolution. 4-wire, write-only (SCK/SDI/CS/LDAC, no MISO). RC low-pass on VOUT → VDBS (amplitude-line noise → RF AM/PM noise = decoherence).

Timing

Pre-stage the DAC code during the dwell, pulse LDAC on the step (the amplitude analog of IO_UPDATE) → the SPI transfer is out of the critical path. Amplitude-path latency is then DAC settling (~µs) + RC, both larger than the VGA's 300–400 ns → amplitude is the slow path; it may lead the frequency step since it needs no ns sync.

RF on/off gating

Requirement: full extinction, phase-coherent (VGA at min still leaks −30/−40 dBm). Rule: keep the AD9912 running (phase accumulator never stops) and gate downstream.

Solution: a high-isolation RF switch in the output path — pSemi PE4251MLI-Z (C2654721; absorptive SPDT, 10 MHz–3 GHz, single 3.3/5 V supply, single-pin CMOS control = ECP5-direct, 62 dB isolation @ 1 GHz, IL 0.60 dB, P1dB +30.5 dBm) — gated from the fast path (ECP5 off step_to_next or a pulser TTL, not the Pico). Because it's absorptive, the deselected throw is internally 50 Ω-terminated — no external RF2→50 Ω resistor and no DC-block caps (RF ports DC-free). Use as on/off SPST: RFC = in, RF1 → output (ON), RF2 = dummy (switch to it = OFF). Its 62 dB in one part replaces the cascaded pair we'd have needed with the reflective PE4259-63 — so a single switch + VGA-at-min + AOM clears >80 dB total off. Caveat: ~150 ns switching (vs the PE4259's ns) — fine for typical AOM gating, but if you need sub-100 ns RF edges fall back to the PE4259-63 (C470892, reflective, needs RF2→50 Ω, cascade 2×).

Pulser ↔ DDS bus

New serial protocol (replaces the old 16-bit parallel): an addressable SPI frame [ADDR(4b) | CMD(4b)][payload…] shared by all boards; each board compares ADDR to its strapped add_in[3:0] and only the match consumes the payload (0xF = broadcast). The timing triggers step_to_next and ram_reset stay dedicated broadcast wires (low-jitter), not buried in frames.

MISO dropped — the DDS board never talks back to the XEM7305 (readback goes to the Pico W). So every backplane signal is an input to the board. Active signals: SCK, MOSI, CS, step_to_next, ram_reset (5).

Backplane / receivers

2× DSLVDS1048 (quad receive-only LVDS) = 8 channels: Rcv1 = SCK/MOSI/CS/step_to_next; Rcv2 = ram_reset + 3 spares (routed backplane→receiver→ECP5 GPIO, input-only). Differential over the backplane; drivers on the XEM7305 side (reserve matching driver channels for the spares).

Termination — multi-drop!

The bus is multi-drop (one driver, all boards tap the same pair). Do not terminate on every card — N × 100 Ω would parallel to 100/N Ω. One 100 Ω per pair at the far end. Decision: populatable 100 Ω on every card, populate only the last-slot (far-end) card; cards are high-Z taps with short stubs. Silkscreen "TERM: populate on end card only".

Pin budgets

Pico W (~15–18 of ~26 GPIO)

  • ECP5 config (slave-SPI): 7 — SCK/MOSI/MISO/CS + PROGRAMN/INITN/DONE (trim to ~5)
  • Command sideband: 2–4 — UART (2) or SPI (4), kept separate from config (avoids accidental reconfig)
  • Peripherals: ~6 — status LEDs (2–3), I²C OLED bus (2, expandable), spares (2–4)

AD9912 access stays behind the ECP5 — the Pico commands the ECP5, which is the sole AD9912 SPI master (bare-board bring-up = load a tiny SPI-passthrough bitstream). SPI1-aux MISO carries ECP5→Pico readback (master-initiated; add an IRQ GPIO for async).

ECP5 → backplane: 6 pins

5 active inputs (SCK/MOSI/CS/step_to_next/ram_reset) through the receivers, across 8 provisioned RX channels; add_in[3:0] = 4 local address straps (not backplane traffic); IO_UPDATE generated locally.

Power

Single 5 V backplane rail is sufficient — every on-board rail is ≤5 V (step-down only), ~1–1.5 A per card (~3–5 W; AD9912 + VGA + Pico WiFi bursts are the hogs). Per-card local regulation off a shared 5 V bus is good for RF (each card filters its own supply).

RF-critical

Never bare-buck the AD9912 analog — switching ripple → RF spurs. Use a buck → low-noise LDO for the 1.8 V and clean 3.3 V analog (per the AD9912 eval board). Regulator parts are lifted from OrangeCrab r0.2.1 (KiCad); the analog LDOs are additions OrangeCrab doesn't have. Sequence the ECP5 rails; add the VCCAUXA PLL filter if a PLL is used.

Assembly

AD9912 (exposed-pad QFN) and the ECP5 (BGA) can't be hand-soldered. Preferred route: bare PCB from JLC (ENIG) → local assembly house does full population, with the critical ICs (AD9912, ECP5, DAC, VGA, oscillator) consigned from authorized distributors (genuine-part assurance) and passives sourced by the assembler.
